## Проблема

Через СБП и счета ДБО проходит 75% денег, украденных у физлиц: 4,91 из 6,52 млрд ₽ во II кв. 2026 по данным Банка России. Жёсткие правила ломаются с двух сторон:

- **Честный клиент** (кейс стажёра Никиты): сменил номер и покупает велосипед с рук. Перевод блокируется, нужен звонок в колл-центр.
- **Жертва социальной инженерии** (кейс бабушки): действует под диктовку «спецслужб», сама подтверждает перевод кодом из SMS. После блока онлайн-перевода её ведут в банкомат.

## Решение: «Светофор» в три коридора

| Коридор | Что происходит | Участие сотрудников |
| --- | --- | --- |
| 🟢 GREEN | Перевод в профиле клиента, получатель знаком. Проверку клиент не замечает | 0% |
| 🟡 YELLOW | Сработал поведенческий признак, но получателя нет в базах ЦБ. Клиент сам снимает подозрение: QR-хэндшейк с продавцом («Радар сделки»), биометрия или подтверждение доверенного лица («Защита близких 2.0») | 0% |
| 🔴 RED | Получатель в базе ЦБ, перевод под диктовку или клиент выбрал «Безопасный счёт». Пауза 48 ч по 161-ФЗ и **лимит 50 000 ₽ во всех банкоматах** | Спецгруппа для 60+ |

Подробнее в [docs/architecture.md](docs/architecture.md): двухконтурный кэш против лага данных в 24 ч, схема блоков и логика скоринга.

## Результаты симуляции

300 000 синтетических переводов, 20 000 клиентов, seed 42 (`python run.py`):

| Метрика | Жёсткие правила | Контекст 360 |
| --- | ---: | ---: |
| Полнота выявления фрода (Recall) | 84,2% | **90,6%** |
| Потери клиентов | 353,0 млн ₽ | **72,6 млн ₽** (−79%) |
| Ложные блоки с ручным разбором | 26 803 | **7 329** (−73%) |
| Честных, прошедших Self-Service без звонка | 0 | **34 594** |
| Стоимость ручного разбора ложных блоков (180 ₽/шт.) | 4,8 млн ₽ | **1,3 млн ₽** |
| Время решения в ядре (Python, без сети) | — | p50 ≈ 2 мкс |

Распределение по коридорам: 85,6% зелёный, 11,6% жёлтый, 2,8% красный.

Основная часть спасённых денег приходится на **кросс-канальный флаг в банкоматы**. В старой схеме жертву после отказа в онлайне ведут к банкомату, и там она теряет всю сумму.

> ⚠️ **Ограничения.** Данные полностью синтетические, а поведение жертв и мошенников задано допущениями в `config.Assumptions`, например «35% жертв уговаривают колл-центр снять блок». Цифры показывают механику, а не прогноз для банка.
>
> Синтетический фрод получился «слишком различимым»: при пороге `green_max=50` доля зелёного коридора растёт до 96%, а потери почти не меняются. На реальных данных так не будет, поэтому пороги калибруются на пилоте (A/B на 5% трафика СБП).

## Быстрый старт

Нужен Python 3.10+, сторонние библиотеки для движка не требуются.

```bash
git clone https://github.com/Nickzps/vtb-context360.git
cd vtb-context360
python run.py                      # полный отчёт
python run.py --transfers 50000    # быстрее
python run.py --green-max 45       # другой порог зелёного коридора
python run.py --json               # результат в JSON
```

Или установить как пакет:

```bash
pip install -e ".[dev]"
context360 --help
pytest
```

**Без установки:** откройте [notebooks/colab_demo.ipynb](notebooks/colab_demo.ipynb) в Google Colab (кнопка выше). Там есть графики, подбор порогов и «свой перевод через движок».

### Свой перевод через движок

```python
from context360 import (Context360Engine, ClientProfile, Recipient,
                        SessionContext, Transfer, ClientBehaviour)

engine = Context360Engine()
nikita = ClientProfile(client_id=1, age=24, typical_limit=30_000, vulnerability_index=2, whitelist={100})
seller = Recipient(rid=555, in_cbr_db=False, account_age_days=900, unique_senders_24h=1)
session = SessionContext(active_call=False, screen_sharing=False,
                         phone_changed_hours=20, me2me_in_24h=0, new_device=False)

d = engine.decide(Transfer(1, nikita, seller, 85_000, session,
                           behaviour=ClientBehaviour(can_qr_handshake=True)))
print(d.corridor, d.reasons, d.resolved_by)
# Corridor.YELLOW ['Новый получатель', 'Сумма в 2.8× выше типичной', 'Признак №9: смена номера ≤48 ч']
# Радар сделки: QR-хэндшейк, продавец рядом
```

## Структура репозитория

```
vtb-context360/
├── src/context360/
│   ├── config.py       # пороги движка и допущения симуляции
│   ├── models.py       # профиль клиента, сессия, перевод, решение
│   ├── engine.py       # Context360Engine (блоки 3–5) и LegacyRules
│   ├── simulation.py   # генератор синтетического потока и сравнение
│   ├── report.py       # текстовый и JSON-отчёт
│   └── cli.py          # командная строка
├── tests/              # сценарии кейса как тесты (Никита, бабушка, флаг АТМ)
├── notebooks/          # демо для Google Colab
├── web/                # онлайн-демо на GitHub Pages (Python в браузере через Pyodide)
├── docs/
│   ├── architecture.md # схема блоков и логика скоринга
│   └── sbp_research.md # разбор СБП: статистика, топ-10 схем и уязвимостей, FedNow / Zelle / Swish / SEPA Inst / BLIK
└── run.py              # запуск без установки
```
